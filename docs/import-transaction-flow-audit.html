总览地图：导入交易审计中枢

中心节点是“一条导入交易最终能不能正确入库”。周围八个分支分别回答：数据从哪来、在哪规整、被哪些智能链路改写、前端看的是哪份数据、筛选/编辑/确认分别信哪个字段。

输入枝 parser 标准化

  • RawBill 保留平台字段：交易时间、金额、商户、支付方式、原始分类、订单号、状态。
  • StandardBill 统一为日期、金额、类型、描述、账户、分类、parser tags。
  • high-risk boundary Money 内部保留 cents，但 StandardBill.amount JSON 面向元；standard-row 与 preview typed columns 都有 cents 合同。

confirmed current-state fact stage2 基底

  • 加载 parser templates、标准行和历史候选。
  • 先做同批/历史 dedup 与转账 materialization。
  • 再生成 ImportPreviewDraft，作为后续智能链路的承载层。

智能枝 规则、学习、LLM

  • 分类规则与内置 fallback 先确定 category_id 与类型。
  • recurring、learning vector recall、LLM recommendation 继续补充信号。
  • 账户规则最后运行，消费稳定后的类型、分类与转账/投资上下文。

存储枝 preview 双合同

  • typed columns：amount_cents、transaction_type、category_id、account_id、selected。
  • payload：展示、matching feedback、parser/learning/LLM/recurring 细节。
  • high-risk boundary 筛选和 confirm 更信 typed columns；展示和信号细节还读 payload。

一条导入交易

正确链路 = 字段含义稳定 + 当前用户身份有效 + 用户编辑不被覆盖 + confirm 重新校验后事务入库。

parse stage2 preview edit filter confirm

前端枝 页面转换

  • ImportPreviewRecord 是接口层 preview 语义。
  • importPreviewTransaction.ts 映射为 ImportTransaction。
  • investigation hint UI 错但接口对，优先查 category/account map、cents 规范化、本地筛选。

confirmed current-state fact confirm 入库

  • 当前前端主路径提交 preview_updates 并保留未补丁选择集。
  • 后端兼容 selected_ids，但最终仍重新加载 selected preview rows。
  • identity validation error 或 requires review 未解决时拒绝入库。

high-risk boundary 错位雷达

  • 金额扩大/缩小 100 倍：查元到分转换。
  • 分类名称对但入库错：以 category_id 为准。
  • 筛选与展示不一致：查 typed columns 与 payload 是否同步。

investigation hint 排查入口

  • 接口已错：查 parser、stage2、preview 写入。
  • 接口对但 UI 错：查前端转换和当前 taxonomy/account map。
  • UI 对但 confirm 错：查后端重载、identity validation、bill create fields。

人工核对清单：按地图走一遍

单行全链路抽样

  1. 用交易时间、金额、商户锁定一条真实导入行。
  2. 保存 parser 输出：RawBill 与 StandardBill。
  3. 保存 standard-row/template/stage2：amount_cents、parser_amount、parser_type、dedup/transfer 信号。
  4. 保存 preview：typed columns 与 preview_payload。
  5. 保存前端模型：ImportTransaction 的 type、categoryId、accounts、amount cents。
  6. confirm 后对照正式 bill 的 amount、category、source/destination accounts。

筛选与跨页选择

  1. 确认当前是否是 server-paged 模式。
  2. 分类筛选分别测试正常分类、__none__、__invalid__。
  3. 账户筛选分别测试 source、destination、缺失、非法。
  4. signal 筛选测试 parser、platform duplicate、transfer、history、learning、LLM。
  5. 跨页选择后刷新，确认 selected 状态来自后端。
  6. 批量编辑或重新分类后重新拉 page 和 facets，检查计数同步变化。
最低排查证据 修导入预览 bug 前，至少固定一条 preview row 的 id 或 page_sort_key，并拿到 parser 标准行、preview typed columns、preview payload、前端 ImportTransaction、confirm 后正式 bill 五个视角。没有这五个视角，字段错位很容易被修到错误层。
