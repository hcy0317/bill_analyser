# 浏览器功能实测矩阵

本矩阵用于从真实浏览器入口验证 Bill Analyser 的主要业务域。它和 Playwright 核心链路自动化互补：人工矩阵覆盖业务页面和外部能力边界，自动化优先覆盖可稳定重复的数据生命周期、关键 CRUD、导入预览确认、列表与统计联动。

## 执行前置

- 后端通过 Rust `bill_http_server` 提供 `REST /api/...`，`/api/health` 返回 `status = ok`。
- 前端通过 `src/web` 启动，桌面端入口为 `desktop.html`，移动端入口为 `mobile.html`。
- PostgreSQL 与 Weaviate 使用本地测试实例，不能指向生产或个人长期数据源。
- 自动化运行时使用专用测试账号和专用运行标记；人工执行时也应使用独立测试账号。
- 导入样本优先使用 `tests/fixtures/import_samples/`，其中支付宝样本用于核心导入链路。
- 每轮执行开始前清理专用测试账号下的旧测试数据；结束时再次清理并记录失败残留。

## 环境矩阵

| 编号 | 平台 | 浏览器视口 | 入口 | 目的 |
| --- | --- | --- | --- | --- |
| ENV-D1 | 桌面端 | Chromium 1440x900 | `desktop.html#/...` | 覆盖完整桌面导航、表格、弹窗、批量操作和统计图表。 |
| ENV-M1 | 移动端 | Chromium mobile profile | `mobile.html#!/...` 或当前路由实际入口 | 覆盖移动导航、紧凑表单、列表详情和核心 CRUD。 |
| ENV-X1 | 手工扩展 | 用户本机主浏览器 | 桌面/移动入口 | 用于视觉、滚动、外部能力和真实输入法兼容性复核。 |

| A-01 | 健康检查 | `/api/health` | 桌面/移动共用 | 启动后端、PostgreSQL、Weaviate | 访问 health 或由测试脚本探测 | 返回 `ok`，details 中数据库与 Weaviate ready；失败时阻断后续自动化 | 核心自动化前置 |
| A-02 | 登录/注册 | 登录页、注册页 | 桌面/移动 | 专用测试邮箱、密码、允许注册，关闭邮箱强校验 | 注册或复用账号后登录、刷新页面、退出再登录 | token session 有效，刷新后仍处于已登录状态，退出后回到登录态 | 核心自动化前置 |

## 核心链路黄金数据

支付宝样本 `tests/fixtures/import_samples/alipay_statement_sample.csv` 的人工预期基线：

- 记录数：6
- 日期范围：2026-01-15 到 2026-01-18
- 收入合计：25.22 元
- 支出合计：40.00 元

自动化脚本在导入预览和确认后应重新读取页面/API 输出，记录实际黄金值；如果 dedup、转账 materialization 或 parser 合同改变导致正式账单数与样本行数不同，测试必须以当前预览/确认 API 的确定输出为准，并在失败报告中展示差异。

## 通过标准

- A 域全部通过后，才允许继续 B 到 H 域。
- B 域核心链路失败时，列表、统计、预算联动相关测试视为阻断。
- 桌面和移动端至少各完成一次登录、导航、主数据 CRUD 和账单列表验证。
- 自动化失败必须保留 trace、截图或报告；人工失败必须记录页面、账号、样本、复现步骤和预期/实际差异。
