Rust profile runtime 会在邮箱变更时校验格式/唯一性、重置 `email_verified` 并记录审计日志；账户/分类引用 ID 必须属于当前用户，头像上传只接受 PNG/JPEG/GIF/WebP 真实图片内容，已接管的 profile/cloud/external-auth 路由直接响应 `OPTIONS` preflight。

Rust step-up runtime 要求当前密码、已配置的操作密码或有效 TOTP passcode 才签发 `step_up` action token。Rust user-data clear runtime 要求当前密码、已配置的操作密码或有效 `step_up` action token；step-up 与 user-data clear 失败认证会写入 auth log 并进入短窗口限流。全量清理覆盖当前用户的账单/预算/账户/分类/分类规则/标签/模板、导入 session/preview/template staging，以及 Rust 导入/学习运行时样本（`import_annotation_samples`、`llm_memory_events`），`user_data` 审计写入保持 best-effort 兼容并记录聚合 affected_count。

Rust DB foundation 额外负责 auth/security schema 的幂等初始化，覆盖 `users` legacy 认证字段补齐、`sessions`、`auth_logs`、2FA 恢复码、external auth 与 profile cloud settings 基础表/索引；2FA 恢复码当前接管 hash/replace/consume/clear/count SQLite primitive，并由 Rust recovery verify 路由一次性消费；2FA 写管理路由当前由 Rust 生成 setup secret/QR、确认启用、禁用并重生成恢复码；step-up 验证当前由 Rust 通过当前密码、已配置的操作密码回退或 TOTP passcode 签发短期 action token；data export 与 data clear 当前由 Rust 按当前 Bearer 用户执行。
